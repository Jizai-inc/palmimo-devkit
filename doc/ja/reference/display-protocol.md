# 顔ディスプレイ通信仕様 — v2

顔ディスプレイは、480×480 の円形パネルを備えた RP2350 ボードで、USB CDC でホストにつながります。FW v2 自体は表情を持ちません。platform が Flash に書き込む**アセット**（画像、GIF、Lottie から変換したベクターアニメーション）を保存して要求に応じて再生し、タップを通知します。このページは FW とホスト側のクライアント（`palmimo_sdk`、Portal、platform の FW・アセット用ツール）の間の契約です。

FW v1（0.1.x）は異なるプロトコルを使い、v2 より前の SDK を使うアプリ向けにも引き続き提供します。platform が両者を切り替えます（[FW の選択](#fw-の選択)を参照）。v2 のクライアントは `HELLO` で判別します。

## 通信と行の文法

- USB CDC を使います。ボーレートの設定は無視します。
- **コマンド**は `\n` で終わる ASCII の 1 行です。`\r\n` で終わる行は `ERR LINE CRLF` で拒否します。空行は無視し、応答しません。キーワードは大文字、引数の区切りは半角スペース 1 個です。
- FW が送る行には次の 3 種類があります。
  - **最終応答** — コマンドごとに必ず 1 つで、`OK …` または `ERR <COMMAND> <REASON>` です。`VERSION`、`STAT`、`PING` と[互換コマンド](#互換コマンド)は v1 の応答行（`VERSION …`、`STAT …`、`PONG`、`OK IDLE` など）を維持します。
  - **転送の進捗** — 転送コマンドとその最終応答の間だけに現れる `OK XFER BEGIN <bytes> ACK=4096`、`OK XFER SEND <bytes> <crc32>`、`ACK <total>` です（[転送](#転送)を参照）。
  - **イベント** — `EVT …` です。進捗行の間も含め、いつでも送信します。クライアントは応答を待つ間、イベントを読み飛ばします。
- FW が送る各行は最大 1,024 バイトです。
- ホストは前のコマンドの最終応答を受け取ってから次のコマンドを送ります。
- ホストが DTR を下げる（ポートを閉じる）と、FW は途中の行と進行中の転送を破棄し、再生と `STREAM` を停止して待機画面を表示します。電源状態は変えません。互換コマンドで表示した `FRAME` は v1 と同じく寝顔になります。

クライアントは未知の HELLO フィールドを無視し、空の `caps=` リストを受け付けます。

## 識別子と数値

- **アセット ID** は `<owner>/<name>` で、最大 127 バイトです。
  - 標準アセットの所有者は `palmimo` です（`palmimo/happy`）。`system.` で始まる名前は[システム画面](#システム画面)です。
  - アプリのアセットの所有者はアプリ ID です（`zip.my-app/welcome`）。アプリ ID は最大 81 バイト、アセットの `<name>` は `^[a-z0-9][a-z0-9._-]{0,39}$` に一致するため、すべて上限内に収まります。
- **スロット ID**（`sid`、アプリが変更できる Lottie のスロット）は `^[a-z0-9_]{1,32}$` に一致します。
- `<crc32>` は CRC-32（IEEE、zlib と同じ）を小文字の 16 進数 8 桁で表します。`<bytes>` と `<total>` は十進数です。
- スロット番号と Flash アドレスは内部の情報で、通信には出しません。

## コマンド

| コマンド | 最終応答 | 備考 |
|---|---|---|
| `HELLO` | `OK HELLO proto=2 fw=<version> caps=<cap,…>` | FW v1 は `ERR HELLO (try LIST)` を返します。v2 クライアントは platform の FW 切り替えを示すメッセージで停止します。 |
| `VERSION` | `VERSION <version>` | v1 と同じ行です。platform のツールは宣言された版とそのまま比較します。 |
| `STAT` | `STAT key=value …` | v1 の全キー（ちょうど 1 つの `power=ON\|OFF` を含む）に加え、`proto=2`、`hz=`、`play=<asset id\|->`、`stream=OFF\|ON`、`margin_us=`（前回の `PLAY` 以降で最小の帯の余裕）を返します。 |
| `PING` | `PONG` | |
| `POWER ON` / `POWER OFF` | `OK POWER <ON\|OFF>` | `OFF` は再生と `STREAM` を停止して寝顔を表示します。 |
| `WAKE` | `OK WAKE` | 起き上がり画面の後に待機画面を表示します。 |
| `BL <0-100>` | `OK BL <n>` | バックライトです。 |
| `ASSET PUT <id> <bytes> <crc32>` | `OK ASSET <id>` | [転送](#転送)です。platform のツール専用です。先に再生を停止します。 |
| `ASSET DEL <id>` | `OK ASSET DEL <id>` | platform のツール専用です。先に再生を停止します。存在しない場合は `ERR ASSET UNKNOWN` です。 |
| `ASSET LIST [<index>]` | `OK ASSET LIST next=<index\|-> <entry> …` | 各エントリーは `<id>:<kind>:<bytes>:<crc32>` で、現在の `kind` は `vector`、`image`、`gif` です。クライアントは他の kind も受け付けます。順序は固定です。`<index>`（十進数、既定は `0`）は最初に列挙する位置です。行に収まらない分は `next` から続きます。 |
| `ASSET INFO <id> [<index>]` | `OK ASSET INFO <id> kind=<kind> bytes=<n> crc32=<crc32> next=<index\|-> params=<sid>/<dim>,…\|-` | `PARAM` で設定できるスロットを固定順序で返します。`<index>`（十進数、既定は `0`）は最初に列挙するスロットの位置です。行に収まらない分は `next` から続きます。存在しないアセットには `ERR ASSET UNKNOWN` を返します。 |
| `ASSET READ <id>` | `OK ASSET READ <id>` | [読み取り転送](#転送)です。 |
| `PLAY <id> [hold_ms]` | `OK PLAY <id>` | アセットをループ再生します。`hold_ms` があれば、その時間の後に待機画面へ戻ります。`STREAM` と `FRAME` を終了し、すべての `PARAM` をリセットします。存在しない場合は `ERR PLAY UNKNOWN`、電源が切れていれば `ERR PLAY POWEROFF`、電源ダイアログが開いていれば `ERR PLAY BUSY` です。 |
| `STOP` | `OK STOP` | 待機画面へ戻ります。`STREAM` と `FRAME` を終了し、すべての `PARAM` をリセットします。 |
| `PARAM <sid> <v1> [v2 …]` | `OK PARAM <sid>` | 再生中のベクターアセットのスロットを上書きします。値は十進浮動小数点数で、個数はスロットの次元に一致する必要があります。再生中のアセットにスロットがなければ（標準アセットが画像に差し替えられた場合など）、`ERR PARAM NOSLOT` です。クライアントは警告として扱います。 |
| `STREAM <w> <h> RGB565 <crc32>` | `OK STREAM` | ライブ映像の 1 フレームの[転送](#転送)です。`1 ≤ w, h ≤ 169`、RGB565 little-endian、`w × h × 2` バイトです。完成後に表示します。電源が切れていれば `ERR STREAM POWEROFF` です。 |

platform 専用コマンドは `palmimo_sdk` では公開しません。FW 自体は送信者を区別できません。

スロットの次元は正の整数で、プロトコル上の上限はありません。クライアントは不正なアセットのメタデータやスロットを警告して省き、有効なエントリーと接続を維持します。応答の構造やページ送りの不正はプロトコルエラーです。

### 互換コマンド

Portal の QR リーダーが `STREAM` に移行するまで、v2 は v1 の `FRAME …` コマンドとその応答、`IDLE`（`OK IDLE` を返し、`STOP` と同じ動作）、`EXPR SLEEPING`（`OK SLEEPING` を返し、寝顔を表示）も受け付けます。他の v1 コマンドは受け付けません。

## 転送

`ASSET PUT` と `STREAM` は、コマンド行に続けて生バイト列の本体を送ります。

1. ホストがコマンド行を送ります。
2. FW が `OK XFER BEGIN <bytes> ACK=4096`、または最終応答の `ERR …` を返します。エラーなら転送は始まりません。
3. ホストがちょうど `<bytes>` バイトの生データを送ります。エスケープも改行の追加もしません。最後に受け取った `ACK` より最大 16 KiB まで先行できます。
4. FW は受信バイト数が 4,096 の倍数を超えるたびに `ACK <total>` を送ります。`<bytes>` が 4,096 の倍数でなければ、最後の端数にも送ります。
5. FW は必ず宣言された長さを消費してから CRC とアセット形式を検査し、最終応答を送ります。クライアントは最後の `ACK` ではなく最終応答で成功を判断します。

- **停止**: 本体の途中で 2 秒間バイトが届かなければ、FW は `ERR XFER TIMEOUT` を返し、ホストが DTR を下げて再接続するまでバイトとコマンドをすべて破棄します。他の転送中断手段はありません。
- **失敗しても前の状態を維持**: `ASSET PUT` の失敗（CRC、形式、Flash、停止、切断、電源断）ではその ID の既存アセットを維持します。`STREAM` の失敗では前のフレームを維持します。
- **容量**: 連続した空き領域に収まらない場合は `ERR ASSET NOSPACE` です。platform が詰め直します（platform のアセット同期を参照）。

`ASSET READ <id>` では方向が逆になります。FW が `OK XFER SEND <bytes> <crc32>`、生バイト列、最終応答 `OK ASSET READ <id>` の順に送ります。ホストはすべてを読み終えてから次のコマンドを送ります。

`STREAM` のフレームはパネル中央に、`floor(338 / max(w, h))` 倍で表示します。FW は受信中のフレームを円形パネルに見えないフレームバッファ領域に保持し、パネルの 1 回の更新でフレーム全体を切り替えるため、新旧のフレームが混ざりません。

## イベント

| イベント | 発生時点 |
|---|---|
| `EVT TAP <x> <y>` | タップを離したとき。座標はパネルの画素で 0〜479 です。どのメニュー項目に当たったかはクライアントが判定します。 |
| `EVT POWER ON` / `EVT POWER OFF` | 画面のダイアログで電源状態が変わったとき。 |
| `EVT TOUCH REINIT` / `OFF` / `ON` | タッチのウォッチドッグが動作したとき。 |

アセットの再生中や `STREAM` の表示中はタップを通知するだけです。FW 自身のジェスチャー（電源ダイアログとデバッグ画面）には数えず、触れている間も再生を続けます。待機画面と寝顔では v1 と同様に数えます。

## システム画面

待機画面、寝顔、起き上がりは、標準アセット `palmimo/system.idle`、`palmimo/system.sleep`、`palmimo/system.wake` が保存されていて有効なら再生し、そうでなければ FW 内蔵の画面を表示します。電源ダイアログと、アセットが保存されていないときの画面は常に内蔵版です。

## 表示のタイミング

パネルの更新は 61.5 Hz です。FW は各 40 行の帯を、パネルが読み終わってから次に読むまでの間に描くため、ティアリングが起きません。1 フレームの描画が 1 更新周期を超える場合、アニメーションは 2 更新ごと（約 30 fps）に更新します。GIF のフレーム遅延は更新周期の整数倍に丸めます。コントラストの高い輪郭が動くときのちらつきを避けるため、動きは約 30 fps（33 ms）以上で作成してください。

## FW の選択

`palmimo_sdk` は必要な顔 FW を宣言するファイルを含みます。アプリの起動時、platform はそのアプリにインストールされた `palmimo_sdk` から宣言を読みます（アプリは実行しません）。実機の FW と異なれば、必要な FW を先に書き込みます。約 3 分かかり、Portal に表示します。

宣言はインストール済みパッケージ内の `palmimo_sdk/display_firmware.json` です。

```json
{"schema": 1, "protocol": 2}
```

platform はアプリの環境からファイルとして読みます。インストール済み配布物の `RECORD` で場所を特定し、シンボリックリンクはたどらず、最大 4 KiB を読みます。`palmimo_sdk` があって宣言がない（または読めない）アプリはプロトコル 1 を要求します。`palmimo_sdk` がないアプリは切り替えを起こしません。
